# Compiler-Development Debugging Workflows

When working on the compiler in Wave for Platform (WfP), it is important to distinguish between three different debugging workflows. 

*(Note: For the general setup guide, see [Issue #42](https://github.com/wavefnd/wave-for-platform/issues/42). For the host/capability matrix, see [Issue #46](https://github.com/wavefnd/wave-for-platform/issues/46).)*

## 1. Compiler Dump Flags

Flags such as `--debug-wave` and `--debug-whale` are used to print the compiler's internal state—such as the Abstract Syntax Tree (AST) or Intermediate Representation (IR)—directly to standard output or a log file. 

These flags **do not** emit debug-info (such as DWARF metadata) into the compiled binary, nor do they start an interactive debugger session. They are solely for inspecting compiler transformations at specific compilation stages.

## 2. Debugging the Rust Compiler Process

This workflow involves debugging the compiler binary itself (e.g., `wavec`, `whale`, or `vex`) using a native debugger. 

*Illustrative Configuration Example:*
- **Executable:** `/home/user/.cargo/bin/wavec` (or equivalent machine-specific path)
- **Arguments:** `build --target amd64-unknown-elf src/main.wave`
- **Working Directory:** `/home/user/projects/my-wave-project`

*Please note: These illustrative paths and arguments do not mean that WfP already launches the compiler this way natively.*

To learn more about the plans to integrate a native debugger for this workflow, see the native debugger backlog issues (e.g., [Issue #86: Add a bounded native Debug Adapter Protocol client for WfP](https://github.com/wavefnd/wave-for-platform/issues/86), along with #87, #88, #89). For details on the native debug adapter used, refer to the [official LLDB DAP documentation](https://lldb.llvm.org/use/lldbdap.html).

## 3. Debugging Generated Wave Programs

This workflow involves source-stepping through the actual Wave program generated by the compiler.

For this to work, the compiler must successfully generate and embed debug metadata (such as DWARF) into the final artifact. Source stepping requires this compiler-generated metadata to correctly map the executed instructions back to the Wave source code. 

Please note that remote debugging and QEMU support for generated programs are separately scoped from local execution. 

For updates on this workflow, refer to the source-debugging backlog issue: [Issue #90: Support Wave source debugging after compiler debug metadata is available](https://github.com/wavefnd/wave-for-platform/issues/90).
